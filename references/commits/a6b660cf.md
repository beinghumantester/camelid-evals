## The bug

The agent's `LiveDriver` read only `message.content` and parsed tool
calls from that text via a family-specific `tool_parse`. But when `tools`
are supplied, the server parses the model's tool call into the structured
OpenAI `tool_calls` field and **empties** `content`
(`api/mod.rs:5890`). So the agent saw empty text, found no calls, and
ended every turn with an empty answer — **the real-model agent loop
executed no tools for any model whose template renders tools** (Llama
3.x etc.). Only the mock/canned test drivers exercised the execution
path, which is why the unit tests passed while the live model produced
nothing.

## The fix

Added `Client::chat_turn` returning the structured `tool_calls` (OpenAI
shape) alongside `content`; `LiveDriver::step` now prefers the structured
calls and falls back to text parsing only for templates that carry the
call in `content`. `chat_blocking` (the plain chat UI path) now delegates
to `chat_turn` and is behaviorally unchanged.

Verified end-to-end per the commit message: the certified agent-eval
(`read_file`) now PASSES with Llama-3.2-3B (emits `read_file`/`search`/
`run_shell` and executes them) — it returned an empty answer before this
fix.

## Why this is scaffold-only in this project, not a regression-museum case

This bug's own regression test requires driving the **agent tool-calling
loop** — a model configured with `tools`, and asserting that
`tool_calls` actually gets populated and executed — not just the plain
`/v1/chat/completions` request/response shape that
`mock-server/server.ts` implements. Reproducing it meaningfully needs:

1. A tool-capable model loaded (per `fixtures/model-profiles.json`, only
   `llama32-3b-instruct-q8` on this laptop has `tools: true` — the active
   profile, TinyLlama, does not).
2. A mock or live agent loop that actually calls tools based on the
   response, which `mock-server/server.ts` does not implement (it only
   simulates the raw HTTP chat-completion surface).

Faking the agent loop in the mock would mean re-implementing
`LiveDriver::step`'s dispatch logic and testing that copy against itself
— the same reason `evals/security/SCAFFOLD.md` declines to fake GitHub
auth-scope logic. See `skills/camelid-agent-testing/SKILL.md` and
`evals/agent/SCAFFOLD.md` for the case shape this would use once a real
tool-executing harness exists.
